## 1. Overview

Chappie uses a **hybrid online/offline** licensing system.
- First activation: requires internet (calls license backend).
- Daily background validation: requires internet (refreshes local cache).
- Offline grace period: 7 days after last successful validation.
- Owner license: validated offline only — never requires network.

Backend: `https://api.chappieai.ru`

## 3. License Lifecycle

### 3.1 First Launch — Trial
1. App generates `hardware_id` (stable UUID stored in Keychain on first run).
2. App calls `POST /license/trial?hardware_id=<id>`.
3. Backend returns trial key + `expires_at` (7 days).
4. App stores license in Keychain: key, plan, expires_at, last_validated_at.
5. App enters trial mode — full functionality for 7 days.

### 3.2 Activation of Paid License
1. User enters license key in Settings → License tab.
2. App calls `POST /license/activate` with key + hardware_id.
3. On success: store key + plan + expires_at in Keychain.
4. App immediately re-validates and updates UI.

### 3.3 Daily Background Validation
- On every app launch: call `POST /license/validate` with key + hardware_id.
- On success: update `last_validated_at` in Keychain.
- On failure (server down): check `last_validated_at` — if within 7 days → allow.
- On failure (403/404): license revoked → show paywall immediately.

### 3.4 Owner License Validation
- Owner license is a signed JWT (Ed25519).
- Chappie validates the JWT signature using the embedded public key.
- No network call needed — ever.
- If JWT signature is valid and plan = "owner" → full access, no expiry check.

## 4. Grace Period Logic

```
On app launch:
  1. Try POST /license/validate
     → Success: update last_validated_at, continue
     → HTTP 403/404: license invalid → show paywall, block app
     → Network error / timeout:
         last_validated_at < 7 days ago → continue (grace period)
         last_validated_at >= 7 days ago → show "Can't verify license" warning
                                           allow read-only mode (no AI calls)
```

Grace period = 7 days. This covers server downtime, travel, network issues.

## 5. Keychain Storage

All license data lives in Keychain — never in UserDefaults or SwiftData.

| Key | Value |
|---|---|
| `license.key` | The license key string |
| `license.plan` | `trial / starter / pro / team / owner` |
| `license.expires_at` | ISO8601 string or empty for owner |
| `license.last_validated_at` | ISO8601 string, updated on every successful validate |
| `license.hardware_id` | Stable UUID, generated once on first launch |
| `license.jwt` | Raw JWT string (owner license only) |

## 6. hardware_id Generation

```swift
// Generated once on first launch, stored in Keychain forever.
// Does NOT use IOPlatformSerialNumber — that changes on logic board replacement.
// Uses a UUID generated by the app — survives Migration Assistant transfers.
let hardwareId = UUID().uuidString  // generated once, then read from Keychain
```

**Why not use system serial number:**
- Changes on logic board replacement.
- Requires entitlement on App Store.
- Our UUID approach: survives Migration Assistant, fails on clean install (by design).

## 7. UI States & Windows

### 7.1 Trial Banner
- Shown in toolbar when `plan == "trial"` and `days_remaining <= 7`.
- Text: "Trial: N days left — Upgrade"
- Click → opens Paywall sheet.

### 7.2 Paywall Sheet
Triggered by:
- Trial expired
- User clicks "Upgrade" banner
- User tries to use Executor tool in Advisor-only plan

Content:
- Three plan cards: Starter / Pro / Team with prices
- "Buy" button → calls `POST /order` → opens payment URL in browser
- "Enter license key" link → opens activation sheet

### 7.3 Activation Sheet
- Text field: license key input (format: CHAPPIE-XXXX-XXXX-XXXX)
- "Activate" button → calls `/license/activate`
- Success: dismiss sheet, show confirmation
- Error: shake animation + error message inline

### 7.4 License Expired Sheet
- Shown when validate returns `is_active = false`
- Blocks all AI functionality
- Same content as Paywall but with "Your license has expired" header

### 7.5 Grace Period Warning
- Non-blocking banner (not a sheet)
- "Can't reach license server — working offline (N days remaining)"
- Shown only when network validation fails and grace period is active

### 7.6 Settings → License Tab
Shows:
- Current plan badge (colored)
- License key (masked: CHAPPIE-****-****-XXXX)
- Expiry date
- Device count (for team plan)
- hardware_id (shown in full — needed for owner license re-issue on new Mac)
- "Deactivate this device" button (frees a slot)
- "Enter new license key" button

## 9. LicenseService (new service in ChappieCore)

```
ChappieCore/Sources/ChappieCore/Services/
└── LicenseService.swift    # actor, owns all license logic
```

Responsibilities:
- Generate / read hardware_id from Keychain
- Trial registration on first launch
- License activation
- Background validation on launch
- Grace period calculation
- JWT verification for owner license
- Publish `LicenseState` for UI consumption

```swift
enum LicenseState {
    case loading
    case trial(daysRemaining: Int)
    case active(plan: LicensePlan, expiresAt: Date?)
    case owner                          // offline, never expires
    case expired(plan: LicensePlan)
    case gracePeriod(daysRemaining: Int)
    case noLicense
}
```

## 11. Ed25519 Public Key (owner license verification)

The public key is embedded as a constant in `LicenseService.swift`.
The private key lives only on the VPS, never leaves the server.
Owner license JWT format:

```json
{
  "plan": "owner",
  "email": "sergej@chappieai.ru",
  "hardware_id": "<uuid>",
  "issued_at": "2025-06-08T00:00:00",
  "expires_at": null
}
```

Signed with Ed25519. Chappie verifies signature → if valid → grant owner access.

## 13. Security Properties

| Threat | Mitigation |
|---|---|
| License key sharing | hardware_id binding, max_devices limit |
| Fake license generation | Ed25519 signature — requires private key on server |
| Binary patching to skip check | Obfuscate check, multiple validation points |
| hardware_id spoofing | UUID in Keychain — not trivially spoofable |
| Server downtime blocks users | 7-day grace period |
| Owner license theft | hardware_id binding + Keychain storage |
| Replay attack on JWT | `issued_at` + 30-day validity window on owner JWT |
| Owner flag hardcoded in binary | Owner check requires valid Ed25519 signature — not a flag |
